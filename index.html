What we are covering today

This workshop will explore the potential of static site frameworks for publishing scholarly projects. Representing a minimal computing approach to presenting information on the internet, static sites offer an option for public scholars and digital humanists that is flexible, customizable, and suited to digital preservation. We will survey a selection of scholarly projects using a variety of static site frameworks and get some hands-on experience building a digital exhibit using Collection Builder.

Digital Scholarship Constraints

  • I might be using a proprietary tool provided by a vendor which requires a subscription
  • I could be using open source software installed on a web server, someone needs to keep current with software updates, security issues, and future releases
  • If my project contains dynamic elements that can’t easily be captured by web archiving software
  • If my project is hosted on a server that I don’t control
  • My research assistant might do most of the technical work on my project

Static Sites

Many existing websites (https://exhibits.lib.utah.edu/) or (https://digitalmatters.utah.edu/) are developed with Content Management Systems, that allow you to create web pages without necessarily knowing underlying technologies of web publishing like HTML (Hypertext Markup Language) and CSS (Cascading Style Sheets).

Static sites generate web pages locally, then publish to the web. Dynamic page elements that are processed on a server are not present.

Static Sites

  • Require some technical skills
  • Built with a variety of programming languages (eg python, ruby, go, rust)
  • Use a simple markup language (Markdown) for content creation

Static vs Dynamic

Static

  • Every user of the web site receives the same content
  • No database = fewer security vulnerabilities
  • Requires some technical skill, ability to edit html and/or markdown files

Dynamic

  • Web content can be personalized, generated “on the fly”
  • Interface for updating content often looks like standard word processing software
  • Databases support more complex information modeling for large-scale projects

More reading: https://researchguides.uic.edu/digital-uic/static-dynamic

Digital Obsolescence

“Between 1996 and 2023, the National Endowment for the Humanities’ Education Development and Demonstration (NEH-EDD) program provided financial support for 59 projects producing free-use digital humanities websites. A recent survey of this program’s funded materials found that while 40 remained online in September 2020, 19 had become unavailable”

The Endings Project

Endings Principles for Digital Longevity, https://endings.uvic.ca/principles.html

Products are the project outputs intended for end-users, typically in the form of websites or print documents. The following principles apply to products intended for the web:

  • 4.1 No dependence on server-side software: build a static website with no databases, no PHP, no Python.
  • 4.2 No boutique or fashionable technologies: use only standards with support across all platforms, whose long-term viability is assured. Our choices are HTML5, JavaScript, and CSS.
  • 4.3 No dependence on external libraries or services: no JQuery, no AngularJS, no Bootstrap, no Google Search.
  • 4.4 No query strings: every entity in the site has a unique page with a simple URL that will function on any domain or IP address.
  • 4.5 Inclusion of data: every site should include a documented copy of the source data, so that users of the site can repurpose the work easily.
  • 4.6 Massive redundancy: every page contains all the components it needs, so that it will function without the rest of the site if necessary, even though doing so means duplicating information across the site.
  • 4.7 Graceful failure: every page should still function effectively even in the absence of JavaScript or CSS support.

Some benefits of a static site approach

  • Static sites do not have many of the security issues that Content Management Systems like WordPress have. More robust when dealing with security issues like bot attacks, malicious crawling.
  • If your project is relatively self-contained, a static site may give you “just enough” functionality.
  • Static sites are portable, also conducive to web archiving for more long-term preservation.
  • Can host anywhere. Many people use GitHub for this.

GitHub! What is it good for???

  • Used as a shared repository for software development. Supports team-based or solo work.
  • Maintains a record of changes for a project.
  • Good for documentation, tracking issues.
  • Has features that allow you to deploy static site pages for web publishing.
  • Free
  • Acquired by Microsoft in 2018

Collection Builder

  • Developed by the University of Idaho Library with federal grant funding
  • Metadata-focused static site solution
  • Used for a variety of Digital Humanities / Public History projects
  • Can walk through some basics in getting started on GitHub without needing to download software locally on your computer
  • Has add-ons that support long form essays and oral histories as data projects
